The Problem

Every product question was a moment merchants faced alone

Merchants browsing Mutual Funds, Fixed Deposits, and Credit Cards inside the app hit the same wall at the same point: a real question with no one to ask. What's a folio? Is my KYC enough? Without an answer in that moment, they either dropped off mid-journey or raised a support ticket — both slow, both expensive.

01

Discovery stalls without a guide

Product pages explained features well, but couldn't answer the one specific question a merchant actually had.

02

Support couldn't scale with growth

Every unresolved question became a ticket, and ticket volume grew in lockstep with the merchant base.

03

One language, one tone, for everyone

Existing help content assumed comfort reading English — not every merchant had either.

Objectives

What Saathi had to be true to

I framed the brief around three jobs the agent had to do, in order, then translated each into an architectural commitment before a line of agent logic was written.

What Saathi Had To Do

01

Educate

Explain Mutual Funds, FDs and Credit Cards in plain, conversational language — in the merchant's own language.

02

Sell

Recognise real buying intent mid-conversation and carry it forward into KYC, folio creation, and the first investment.

03

Support

Once a merchant is onboarded, resolve account and transaction questions independently — no ticket, no wait.

Architectural Goals

01 Keep one Master Agent responsible for guardrails, roles, and routing — never for answering directly.
02 Give each product its own Child Agent, so Mutual Fund logic never leaks into a Credit Card answer.
03 Ground every Child Agent's answer in one shared RAG knowledge base, not per-agent memory.
04 Stream voice bi-directionally over WebSocket for a real, low-latency conversation.
05 Support multiple Indian languages without maintaining separate agents per language.
06 Log every session for hallucination review through golden-set evaluation.
07 Hand off cleanly to Core Banking APIs once intent turns into an action.
08 Scale on GCP with concurrent voice sessions, without touching agent logic.

The Solution

Saathi: a voice-first agent woven into product discovery

Rather than one monolithic bot, Saathi is a small hierarchy — a Master Agent that holds the guardrails, and product specialists underneath it that actually answer.

Interaction Flow
State 01 · Idle
Saathi rests as a quiet floating button — present, never intrusive.
State 02 · Nudge
A contextual nudge — "Have a question? Ask Saathi" — invites the first tap.
State 03 · Activated
Tapping opens the voice channel — Saathi is live and listening.
State 04 · User Speaks
The mic glows as voice streams in over WebSocket, in real time.
State 05 · Listening
Saathi holds the floor open, capturing full intent before responding.
State 06 · Responding
A spoken answer plays back; "tap again to close" keeps control with the user.
State 07 · Resolved
The screen settles back to idle — the merchant continues browsing, uninterrupted.
Agent Architecture
01

The client streams voice bi-directionally over WebSocket into the agent layer.

02

The Master Agent enforces guardrails and role definitions first, then reads intent — it never answers directly itself.

03

The Master Agent routes the turn to the right Child Agent — Mutual Fund, Fixed Deposit, or Credit Card.

04

The Child Agent answers using its own product logic and tools, grounded in the shared RAG knowledge base.

05

Where intent turns transactional, the Child Agent hands off to Core Banking APIs — KYC, folio creation, transactions.

06

GCP carries compute, logging, and monitoring underneath every step, with golden-set evaluation catching hallucination.

Grounding & Guardrails

Judgment sits above the answer, not inside it

Owned by the Master Agent

Role and policy definitions — what any agent is and isn't allowed to say.
Intent routing — deciding which Child Agent owns a given turn.
Session and conversation-state control across the full voice interaction.
Escalation to human support when intent falls outside any Child Agent's scope.

Owned by the RAG Layer

One consolidated source of product data, policy docs, and FAQs.
Every Child Agent retrieves and grounds its answer here — no agent improvises from memory.
Continuously updated as products, rates, and policies change.
Checked against a golden-set evaluation framework to catch drift and hallucination.
